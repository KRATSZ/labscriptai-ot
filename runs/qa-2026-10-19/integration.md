# Flex plugin integration and release — 2026-10-19

Integration PR https://github.com/KRATSZ/labscriptai-ot/pull/9 includes #5–#8. Follow-up unifies the download and improves user interaction. Goal: a general, lightweight Opentrons Flex plugin; retain the existing authoring/runtime harness.

Implemented: 52 consolidated MCP tools; preserved local removal of host wake adapters; modules/stacking, waste chute and keyed online preview; shared protocol analysis cache; corrected watch resume budgets and recovery guidance; cross-platform runtime installer; optional vision defaults off and reports skipped checks honestly; repaired dilution templates. No new service framework, database or model dependency.

Release build: `python3 scripts/package_labscriptai_ot.py` creates one `dist/labscriptai-ot-0.1.1.zip` with all five detailed module models enabled by default, plus `release-manifest.json` with exact size/hash. The earlier separate core/detail packaging is superseded. Runtime OBJ meshes and provenance are included; environments, secrets, tests, QA notes, training weights, Blender sources and duplicate exports are excluded. Dependencies install locally. Successful rebuilds remove stale plugin ZIPs, preserving unrelated files.

Verified: 359 Node tests, 9 Python tests and 3 packaging tests pass. A fresh ZIP installs and setup reports 19 pass, zero warnings/failures. Five detailed-model geometry/motion tests also pass against the actual extracted ZIP. The viewer now survives its launching client exiting, uses an independent private startup log, and retains readiness/PID identity and startup timeout checks. Linux CI exposed eager server-side OpenGL creation; browser preview now loads meshes without it and allocates an image renderer only for explicit JPEG requests. The regression disables OpenGL and checks health, info and scene payload after the client exits. Real browser rendering and step-to-scene navigation passed after DeepSeek Harness exited.

Actual DeepSeek Harness (`deepseek-v4.1-flash`) exercised environment setup, ambiguous well mapping/tip policy, authoring eight independent sample transfers with simulation + LogicPass + four 3D checks, repairing an invalid pipette name and revalidating, missing robot IP/operator handling, and persistent preview. The repair changed exactly the invalid pipette name. Baseline runs exposed verbose speculative answers and redundant report work; one baseline authoring attempt timed out at 600 seconds and is not counted as passed. After changes, the complete local authoring/check/preview case finished in 61 seconds in this environment (an observation, not a performance guarantee). A mounting error in the first harness setup was corrected before direct-MCP scenarios. Clarifications now focus on blocking facts, recommend a conservative provisional tip policy, and avoid invented carryover percentages; structured status is kept out of routine chat.

No physical robot actions were performed. Simulation, LogicPass and the illustrative 3D models do not establish physical readiness or assay accuracy. Full host-client UI installation in Codex/Claude Code/Cursor has not been claimed as tested; real stdio MCP and DeepSeek Harness integration were tested.
