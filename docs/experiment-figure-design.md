# 实验配置图：调研与接入建议

更新：2026-11-03。状态：0.1.3 已实现通用起始配置图并接入模拟与动画入口；安装包真实 MCP 验收与独立浏览器用户流程验收通过。下面保留设计调研与后续方向，实际实现范围以本节为准。

## 0.1.3 实现与范围

- `simulate_protocol` 成功分析后自动返回 `experiment_figure` 路径与 MCP PNG 图像内容。现有 verify/run skill 已说明如何直接呈现图片；不增加必须记忆的工具或命令。
- `flex3d_open_viewer` 同时返回图片与配置页；动画工具栏新增「实验配置图」链接。配置页支持多页 PNG 预览/下载、完整逐孔 CSV/JSON、协议中可确认的载具间移液路径、返回动画。图片失败不改变模拟结论，配置页提供返回动画入口。
- 新增 `automation/figures/experiment_figure.py` 和 `servers/opentrons-mcp/lib/experiment-figure.js`。读取同一 analyze JSON，不执行协议文本、不访问机器人、不依赖 MuJoCo。缓存绑定分析字节、渲染器与字体版本。发行包包含绘图脚本和 OFL 中文字体。
- 支持 Flex/OT-2 台面编号、模块/适配器叠放、PCR 模块占位、载具真实孔位坐标、起始液体身份与声明体积、分页。`loadLiquid` 重复声明按现有模拟器语义覆盖，不推断为混合。声明 0 μL 的孔与未声明孔分开，未声明不推断为空或未使用。
- 首版是**起始配置**：不重写液体账本，不把分液总量当成最终孔体积，也不从试剂名解析或推算浓度。最终配方、重复/对照语义与按步骤切换仍是后续功能，不在本次实施范围。图像标签过长时截短，配置页/逐孔表保留全名。
- 协议模拟失败不生成成功配置图；后置装液声明无法用单一起始图表达时，明确返回图片生成失败并保留模拟/动画。`extra_args` 的旧模拟路径可能没有 analyze JSON，返回图片不可用。升级前已启动的旧动画服务需要关闭重开以使用新页面路由。

测试与交付记录集中放在 `.agent-runs/experiment-figure-20261103/`，实际运行产物在 `PLUGIN_DATA/artifacts/experiment-figures/`。

验证：407 项 Node 检查通过；68 项 Python 检查完成（4 项原有条件跳过），随后 5 项装液声明/绘图检查复验通过；4 项打包检查通过；插件清单及 Claude 校验通过。解压安装包的 stdio MCP 跑通 Flex/OT-2 分析、图片内容、配置页与动画重开。独立 usability_tester 按 user-journey-test 实际打开和下载两页 PNG/CSV，核对 1000 μL、80 μL 与未声明孔；故障图页可理解且能返回动画。没有实机测试。

已知不阻断项：长适配器名称在小图卡片中可能截断，完整名称保留在配置 JSON。后续若扩展图卡再改善换行，本次不增加编辑器或扩展最终配方计算。

## 推荐方向

在三维过程预览之外，增加由结构化数据生成的二维实验配置图。默认展示「台面怎么摆、起始装什么、配完每孔有什么、液体从哪到哪」。采用论文多面板图的排版：白底、细线、清楚的坐标、少量语义色、直接标注和独立图例。不是宣称符合某家期刊的投稿要求。

参考图的问题：第一张把初始状态、中间工作液和最终反应板混在一张长图里，文字大量塞进孔内；第二张用大色块表示器材，缺乏形状线索，硬件占位与实验耗材混淆。两图的板位、吸头位置和反应孔数不同，不能拼成同一实验事实。

样稿采用项目既有 ADH1 记录作为内容示例，不采用第二张图的摆位；ADH2 应另生成图并保留独立样品身份。样稿是人工编排的设计预览，不是新一次协议验证，也不是现场台面记录。

## 信息结构与视觉规范

| 面板 | 默认呈现 | 详细信息 |
| --- | --- | --- |
| A 台面 | 按机型的俯视位置、操作者朝向、耗材小图形、槽位和模块叠放 | 型号、适配器、固定硬件占位、吸头规格；协议未占用不等于现场为空 |
| B 起始装液 | 槽位/孔位、试剂名、原液浓度、要求装液量 | 预装/机器人后配、数据来源；浓度未知则写未知 |
| C 目标孔板 | 完整行列、处理组/对照/重复、变量单位、每孔总体积 | 每孔组分、各组分体积、名义终浓度、来源孔；支持多板 |
| D 液体路径 | 主要来源→工作液→反应板，特别标出人工步骤 | 点孔可查看转移记录；复杂转移合并成组，避免满屏箭头 |

- 固定语义：处理孔用蓝绿、无酶对照用琥珀描边，搭配文字/线型；颜色不作为唯一线索。浓度用数值表达，不能用同一颜色同时表示试剂身份、浓度和组别。
- 孔内尽量只放一个主变量；相同信息移到行列标题和图例。避免每孔重复写「有酶」和单位。
- 未使用、已知空孔、未知内容、被排除孔分开编码。未声明液体不等于空孔。
- 明确初始装液、某步骤后的预测状态与最终配制状态；切换时同步标题和步骤，不能统一写成「当前实际状态」。
- 交互版点击或键盘选孔显示配方与来源；静态版必须保留图例、关键信息和配套逐孔表，不能只靠悬停。
- 推荐 SVG 为图形母版、PNG 为聊天预览，后续按需要导出 PDF。孔板、储液槽、管架按实际几何与 ordering 渲染，不能全部硬编码 8×12。

## 仓库已存在的接入点

以下为本次代码核对结果，不把路线图里的计划当成已实现功能：

- `automation/flex3d/sim/flex_protocol.py`：`load_analysis()` 读取液体身份与载具；`Planner.run_commands()` 消费 `loadLiquid`，`State.wells` 跟踪各液体组分体积，可作为复用候选。它是体积模拟，不自动提供完整实验语义或经实测的浓度。
- `automation/flex3d/sim/ot2_runtime/`：已有 OT-2 独立运行时；新图须同时考虑其编号台面，不能复用 Flex 槽位规则。
- `automation/flex3d/sim/web_player.py`：`Model.info()` 已暴露协议、步骤、槽位等；当前接口没有完整逐孔配方展示。`automation/flex3d/viewer.html` 与 `web/viewer.js` 可增加「实验配置」视图。
- `servers/opentrons-mcp/lib/flex3d.js`：现有预览生命周期入口。新静态绘图不应强制依赖 MuJoCo/三维场景构建才能工作。
- `servers/opentrons-mcp/lib/state.js`：已有 declared/simulated/observed/reconciled 来源语义，应保留字段来源，不能把模拟值包装成现场已核对值。
- `skills/opentrons-protocol-author/SKILL.md` 已要求 `define_liquid` / `load_liquid` 与 `design-notes.json`；适合补充实验条件、重复、对照和浓度语义。
- `docs/ROADMAP-experiment-run.md` 规划了 Experiment/Run 和报告归档；本功能沿其方向接入，不先新建数据库或另一个业务实体。

## 推荐实施顺序

1. **先统一数据，再做渲染。** 增加小型二维图数据适配层，读取同版本 analyze JSON 与设计注释。生成用于渲染的 JSON，绑定协议哈希、机型、参数取值、所选步骤和输入版本；它是产物，不是新的业务对象。三维与二维读取同一份分析结果，优先复用已有液体计算，避免再写一套独立账本。
2. **补语义缺口。** 来源液体、孔内容和名义终浓度分开。分析结果没有浓度、重复或对照标签时，从有来源的结构化设计数据获取；缺失显示未知。只在单位、原液浓度、混合模型均明确时计算名义终浓度；不从液体颜色、名字或体积比例猜浓度。图与注释冲突须显示差异，不能偷偷覆盖。
3. **先交付静态配置图。** 初期支持台面、起始装液表、最终孔板和逐孔表。用户通过现有编排获得协议/3D/配置图链接；协议修改或参数更改后重建。模拟失败时允许展示有依据的起始配置，最终态显式不可用；不沿用旧版成功图。
4. **再接入交互视图。** 增加台面/孔板与来源详情，先提供「起始/最终」两态，再扩展按步骤查看。初始态需完成声明装液，不能把播放器时间零点尚未消费 `loadLiquid` 的空状态画成起始准备要求。搬板、模块叠放与离台操作按所选步骤定位；连接三维时使用共享 command index。
5. **最后固化 skill。** 根据通用生成器的真实输入输出，决定在现有 author/verify/run skill 内加入调用说明，或新建窄职责 `opentrons-experiment-figure`。推荐先复用现有编排，只有按需单独出图确有需要再新增 skill。无需让插件用户安装一整套学术技能包。

实现采用 `servers/opentrons-mcp/lib/experiment-figure.js` 管理产物，独立二维绘图脚本负责渲染；复用已有 MCP 入口，没有新增工具。

## 首版验收要点

- ADH 示例：独立样品、5 个预装来源、8 档梯度、24 个反应孔和 8 个无酶空白；0 mM/无酶时水替代正确。全部 96 孔坐标和朝向正确。
- 至少一个 OT-2 示例：编号台面、多槽模块、载具定义与孔排序正确；不得回退为 Flex 台面。
- 未声明液体、缺少浓度、设计注释冲突、模拟失败均不输出虚假的已知值或最终态。
- 初始/最终/中间步骤与共享分析一致；多通道、串稀、混合、搬板等操作须在声称支持之前验证。
- 协议/参数改变后旧图失效；长中文名不溢出；导出静态图无需网络、API key 或机器人连接。
